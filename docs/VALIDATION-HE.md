# תוצאות אימות — 8 באוקטובר 2026

הבדיקות בוצעו על נתונים מלאכותיים בסביבה מקומית, עם PHP 8.3.35, Apache 2.4 ו־MySQL 8.4.11. את חיבור הקול בדקנו עם אירועים חתומים מקומיים; לא נפתח שירות מענה ולא בוצעה שיחה.

## עבר

- התקנת מיגרציות על מסד ריק, הרצה חוזרת שאינה מתקינה שוב, יצירת מנהל וחברת MasterLocknKey הראשונה; doctor עובר.
- בדיקות תחביר לכל 150 קובצי PHP באפליקציה ובתוסף; בניית CSS מקומי.
- יצירת לקוח, ליד, תזמון, השלמת עבודה, חומרים משני בעלי מלאי, עמלת אשראי וחלוקת הכנסה; דוגמת $1,000 מחזירה רווח $660.
- שינוי עמלות אינו משכתב עבודה שהושלמה; השלמה חוזרת אינה גורעת מלאי פעמיים. העברה לרכב עובדת והעברה מעבר למלאי נדחית.
- פרטי חברה, לקוח וכתובת חיוב ננעלים ב־snapshot חשבונית; לוגו נשמר גם אחרי מחיקת לוגו החברה; חשבונית כפולה נדחית ו־PDF נוצר.
- כניסה, מסכים ראשיים, חסימת קבצי config/SQL/scripts, CSRF, הרשאות מנהל, רענון תפקיד ממסד, ביטול session למשתמש שנמחק והגבלת ניסיונות כניסה.
- checksum שגוי של מיגרציה נכשל בבדיקת readiness, והחזרתו מתקנת readiness.
- חתימות HMAC: גוף מקורי, מפתח שגוי, תאריך ישן/עתידי; פורמט Retell מול מקור SDK רשמי.
- API מקומי: קליטה חתומה, דחיית חתימה שגויה, agent לא מוכר, payload גדול, מניעת כפילויות והתנגשות event_id.
- worker: פניות אתר ושיחה, סדר אירועים הפוך ללא נסיגת מצב, תמליל כבוי, שיוך חברה לפי המפתח ואישור אנושי שאינו יוצר עבודה נוספת בניסיון חוזר.
- WordPress: הפעלה על ליבה אמיתית במסד מבודד, shortcode, Cron ותור עמיד. תעבורת HTTP מדומה: חתימה, TLS ובלי redirects; שמירה אחרי כשל, ניסיון חוזר עם אותו מזהה, ניקוי פרטי קשר אחרי מסירה וללא שליחה חוזרת של פנייה שנמסרה.
- חילוץ חבילת SiteGround, התקנה במסד נוסף ריק והרצת תהליך עסקי ו־HTTP/PDF עם קוד פרטי לצד התיקייה הציבורית.
- אריזת release: manifest ו־checksums, הפרדת תיקייה ציבורית/פרטית, היעדר config מקומי, סיסמאות, נתוני עסק ותיקיות פיתוח בארכיון.

## תיקונים שעלו בבדיקות

נוספה יצירת Main Warehouse עם מזהה 1 בהתקנה חדשה: הקוד המקורי מסתמך עליו בעת הכנסת מלאי. נוספה working_dir ל־Compose כדי שפקודות CLI המתועדות יעבדו. בדיקות מקומיות הביאו גם לתיקון הרשאות קבצים ב־bind mount ושם סקריפט Python שהתנגש בספריית http.

בסביבת הענן הזו Docker משתמש באחסון VFS שצורך הרבה שטח. מסד הבדיקות הועבר ל־bind mount ב־/tmp, ותוצרי הדגמה קודמים גובו לפני פינוי ממוקד. זו התאמה לסביבת הבדיקה, ולא דרישה של SiteGround או של מחשב פיתוח רגיל.

## עדיין דורש בדיקה בחשבון האמיתי

אין גישה ל־SiteGround: PHP CLI, MySQL, SSL, הרשאות storage, Cron, WAF/cache, גיבוי ושחזור חייבים להיבדק שם. לא בוצעה העברת HTTPS מלאה משרת WordPress ציבורי לשרת SiteGround; נבדקו שני הצדדים בנפרד והפרוטוקול מקומית. GitHub Actions מוגדר בקוד; תוצאות הריצה בענן GitHub דורשות בדיקת ה־workflow לאחר push.

לא בוצעו load test, ביקורת אבטחה מקיפה, אישור מסמכי מס, אתר WordPress ציבורי מלא, API לשליפת מידע בזמן שיחה, מנוע תעדוף/מסלולים או שיגור אוטומטי. אלו אינם כלולים בטענת ההכנה לפריסה.
